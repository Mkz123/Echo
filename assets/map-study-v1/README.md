# 场景素材提案 01 · 尚未接入游戏

直接用浏览器打开 [preview.html](preview.html)。图集和数据已内嵌，单个预览 HTML 可离线运行，无需开端口，也没有音频。

## 交付

- 5 套场景原画图集与对应生成提示词，使用内置 imagegen。
- 75 张纯背景（地面与墙体）和 75 张带道具、机器人预览：15 关 × 5 场景。
- 15 张黑白地形掩码。
- 80 张独立透明/地形 PNG：每场景 16 张，包括按钮两态、定时机关两态、箱子、门开关、反向门、单人闸机两态和 47 四向。
- 场景对比、道具状态、机器人四向总览，以及坐标核验记录。

游戏实际登场组合为 36 个；另外 39 个组合用于比较同一关的场景风格，预览中明确标注，不改变关卡的实际场景顺序。

## 如何保证格子一致

1. 从当前 `echo.html` 的 `CORE-START` 至 `CORE-END` 执行原有纯逻辑，读取 `LEVELS`、`parseLevel()`、`initialState()` 和 `SCENES` 规则，提取原始地图与初始门状态。没有让图片模型猜测关卡的路径。
2. 原始字符 `#` 始终是墙体，其余字符提供地面。角色、按钮、定时器、箱子、门、反向门、闸机、出口都按原坐标放置；`manifest.json` 保存每一项的 x、y、类型和关联颜色。
3. 图片模型只生成可重复使用的材质、障碍外观和透明物件，不生成自由构图的关卡全景。渲染器按原始格子铺图，每个墙体和物件都裁切在自己的逻辑格内，墙体装饰不能侵入路径。
4. 地面只采样原画中的平整材质片段；每个逻辑格只绘制一个方格，避免原画地砖细分被误看成额外可走格。
5. 门、箱子、闸机和角色不烘焙进纯背景。背景 PNG 中只有地面与墙体，之后接入时应继续由游戏逻辑控制交互物件。
6. 每关的五个场景共用同一份地图和机关清单，已逐格比较地形掩码与物件坐标摘要。背景图导出为 64 px/格，宽高严格等于地图列数/行数乘以 64。

**地面不等于无条件可走。** 门会开关，箱子可推动且暂占格，单人闸机有使用条件，出口只在最后的空间站开放。因此预览的“地形核对”用绿色表示普通地面、黄色表示条件格、深色表示墙体。“触发状态示意”只是道具状态展示，不是一次真实游戏模拟或通关解法。

## 文件

- [交互预览](preview.html)：可选择关卡、场景、角色朝向、地形视图与机关状态；鼠标指向格子可读坐标。
- `maps/<scene>/01-background.png`：纯地面与墙体，64 px/格；同目录 `01-preview.png` 为初始道具与机器人预览。编号 01–15。
- `masks/01-terrain.png`：白色为非墙体地面，黑色为墙体，32 px/格。
- `sprites/<scene>/`：地形与道具 128 × 128，机器人 192 × 192，透明背景；源切片方向在 `atlas-metadata.json` 中明确标注。
- `atlases/<scene>.png`：原始透明图集；WebP 为离线预览使用的压缩版本。
- `prompts/<scene>.txt`：五套原画的完整提示词。
- [场景总览](review/scene-overview.png)、[道具状态](review/prop-states.png)、[机器人四向](review/robot-turnarounds.png)。
- `manifest.json`、`scene-spec.json`、`atlas-metadata.json`、`validation.json`：地图、风格、源切片边界与核验结果。
- `renderer.js`：独立预览的铺图代码，未被游戏引用。

## 验证与限制

75 个组合逐格通过：同关卡的五种场景地形掩码一致、机关坐标一致，所有特殊标记都位于非墙体格；地图图像与逻辑格子具有固定像素对应。离线 Chrome 检查无 HTTP 请求和脚本错误，预览支持桌面和手机。

图集按真实透明间隙切分，不假设模型输出的四行等高；修正了天线被裁和邻格碎片混入的问题。服装及四向已人工查看。这一版用于确认视觉效果，尚不包含行走帧动画、角色按下按钮时的遮挡层、各计时剩余段逐帧状态或全部门朝向变体；这些属于接入前的后续工作。当前所有物件保持单格占位，未改变碰撞规则。

`echo.html` 的文件摘要与素材制作前一致，正式关卡和背景音乐没有改动。

维护用提取和导出脚本保存在 `tools/`；提取仅依赖 Node，批量渲染脚本需 Playwright。打开预览页无需这些工具。
